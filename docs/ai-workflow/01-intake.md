# 01 · Intake（需求澄清）

## 目标

把模糊需求变成**可验证**的问题陈述；未澄清前不写业务代码。

## 输入

- 用户自然语言需求
- 可选：截图、API 草稿、现有模块名

## AI 必须问清的问题（缺一则主动追问）

1. **主体**：平台能力还是某个业务应用？应用代号是什么？
2. **租户**：是否跨租户？是否仅当前租户？是否平台超管操作？
3. **角色**：哪些角色可做？权限码是否已有？
4. **范围**：只要 API / 只要 UI / 全栈？是否含 migration？
5. **成功标准**：用什么现象证明完成？（页面、接口、数据结果）
6. **非目标**：明确不做的事，防止范围蔓延

## 输出模板

```markdown
## Problem
<一句话>

## Actors
- 角色 / 权限：
- 租户范围：

## In scope
-

## Out of scope
-

## Success criteria
- [ ]

## Constraints
- 兼容性 / 期限 / 技术限制
```

## 出口条件

- [ ] 成功标准可测试
- [ ] 租户与权限边界清楚
- [ ] 已标明 server / web / deploy 哪些会动
- [ ] 进入 [02-plan.md](./02-plan.md)
