# 多租户模型

## 默认决策

**共享数据库 + 行级 `tenant_id`**（详见 [adr/0001-shared-db-tenant-id.md](./adr/0001-shared-db-tenant-id.md)）。

## 核心概念

| 概念 | 说明 |
|------|------|
| Tenant | 租户，数据与开通应用的边界 |
| Platform admin | 可管理租户本身（创建/停用/配额） |
| Tenant member | 仅能访问所属租户数据 |
| Tenant context | 请求级租户身份，由认证中间件注入 |

## 隔离规则

1. 所有租户业务表含 `tenant_id`（或等价列）。
2. 读写必须经统一 DB scope / repository 助手；禁止业务手写「有时带有时不带」。
3. 跨租户操作仅允许平台级 API，并强制审计。
4. 缓存 key、对象存储路径、消息队列分区需包含 `tenant_id`。

## 请求解析（约定）

优先级（实现时可调整，但须文档同步）：

1. 已认证用户绑定的租户
2. 显式租户头/参数（仅当角色允许切换时）
3. 否则拒绝

## AI 实现检查

- [ ] 新表是否有 `tenant_id` + 索引
- [ ] 列表/详情/更新/删除是否都带 scope
- [ ] 测试是否包含跨租户拒绝
